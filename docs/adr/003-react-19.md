# ADR-003 — React 19 comme version minimale

- **Statut** : Accepte
- **Date** : 2026-02-27

## Contexte

Les packages `@granit/*` declarent `react: "^19.0.0"` dans leurs
`peerDependencies`. Ce choix impose aux applications consommatrices d'utiliser
React 19 au minimum.

React 19 introduit plusieurs fonctionnalites exploitees par le framework :

- **React Compiler** : optimisation automatique des re-renders (remplacement
  de `useMemo`/`useCallback` manuels)
- **`use()` hook** : lecture de promesses et contextes dans le rendu
- **Actions** : integration native avec les formulaires et mutations
- **Ameliorations du Suspense** : support natif du streaming SSR (meme si
  les applications actuelles sont SPA)
- **`ref` comme prop** : suppression du besoin de `forwardRef` pour les
  composants wrapper

## Decision

Fixer React 19 comme version minimale dans tous les packages `@granit/*`
qui ont une peer dependency sur React :

```json
{
  "peerDependencies": {
    "react": "^19.0.0"
  }
}
```

Ne pas supporter React 18 ni les versions anterieures.

## Consequences

### Positives

- **API moderne** : le code du framework peut utiliser les nouvelles API sans
  conditions ni polyfills
- **Performance** : benefice automatique du React Compiler dans les
  applications consommatrices
- **Simplicite** : pas de branches conditionnelles pour gerer plusieurs
  versions majeures de React
- **Forward-looking** : les applications guava-front et guava-admin sont deja
  sur React 19, pas de dette technique

### Negatives

- **Exclusion** : les applications encore sur React 18 ne peuvent pas utiliser
  les packages `@granit/*`
- **Ecosysteme** : certaines bibliotheques tierces peuvent ne pas encore
  supporter React 19 (risque transitoire)
